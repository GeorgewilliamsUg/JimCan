### `design-system.md`

Will define how the interface is constructed.

Use it for:

- Colour tokens
- Typography tokens
- Spacing, radius, border, and shadow tokens
- Icon rules
- Component anatomy
- Component variants
- Interaction states
- Usage guidance
- Component accessibility requirements

### `screens.md`

Will define what each screen contains and how it behaves.

Use it for:

- Screen purpose
- User and permission context
- Route and entry points
- Layout regions
- Primary and secondary actions
- Data fields
- States
- Responsive behaviour
- Acceptance criteria

### `flows.md`

Will define how users move through the product.

Use it for:

- End-to-end journeys
- Navigation paths
- Success paths
- Validation and recovery paths
- Approval and locking flows
- Offline and sync journeys
- Public versus authenticated flows

### `states.md`

Will define behaviour when a screen is not in its normal state.

Use it for:

- Loading
- Saving
- Empty
- Validation error
- Server error
- Permission denied
- Offline
- Sync pending
- Conflict
- Locked
- Archived
- Zero, negative, and very large values
